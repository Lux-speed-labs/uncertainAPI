# Migrating from UncertainAPI 0.1.x to 0.2

UncertainAPI 0.2 is an intentional architectural reset.

## What changed

The 0.1.x line was a Django/DRF web extraction framework built around:

- `ExtractorView`;
- AG2 multi-agent orchestration;
- built-in Playwright/Selenium/httpx browser backends;
- Django models and migrations;
- DRF serializers;
- Django project/app scaffolding;
- prototype task schedulers.

The 0.2 line is instead a lightweight, framework-independent execution runtime built around:

- `IntegrationPlan`;
- dependency-injected protocols;
- source adapters;
- deterministic mapping engines;
- contract validators;
- optional provider integrations.

## Why

The previous architecture coupled extraction, HTTP serving, persistence, AI reasoning, browsers, scheduling, and framework configuration into one package. That made the package heavier and made it difficult to embed outside Django.

The new architecture separates commodity infrastructure from CertainAPI-specific contract semantics and allows mature OSS implementations to plug in behind stable interfaces.

## Compatibility

0.2 is not intended to preserve the old `ExtractorView` API.

Projects that require the original Django architecture should remain on the latest 0.1.x release while migrating.

The 0.1.x implementation remains available through PyPI releases and repository history.

## Migration direction

Old:

```text
Django request
→ ExtractorView
→ AG2 orchestrator
→ browser backend
→ DRF response
```

New:

```text
IntegrationPlan
→ IntegrationRuntime
→ SourceAdapter
→ MappingEngine
→ ContractValidator
→ ExecutionResult
```

Frameworks, queues, storage systems, and observability tools may integrate with the runtime, but they no longer define it.
